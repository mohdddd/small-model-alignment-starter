# Small-Model Alignment: SFT + DPO on Qwen2.5-0.5B

This is our code for PA2. We wrote our own SFT and DPO loops (no HF `Trainer` and no TRL) for `Qwen/Qwen2.5-0.5B`, trained a persona model on `HuggingFaceTB/SmolLM2-360M-Instruct` with the TRL `DPOTrainer` and LoRA, and then compared the models with a blinded pairwise LLM judge. Everything was run on Kaggle with two T4 GPUs.

## Layout

```text
submission_adapter.py        grading interface -> thin wrappers around src/pa2/core.py
src/pa2/core.py              batching, response-only masking, log-probs, SFT loss, DPO loss
src/pa2/prompting.py         the single prompt template (SFT, both DPO runs, Qwen evaluation)
src/pa2/data.py              dataset filtering / single-turn extraction / AlpacaEval subset
scripts/prepare_data.py      download + filter -> outputs/data/*.jsonl (+ data_stats.json)
scripts/train_sft.py         Task 3 SFT loop
scripts/train_dpo.py         Task 4 DPO loop (used for both HH-RLHF and UltraFeedback)
scripts/train_lora_dpo.py    Task 5 TRL DPOTrainer + PEFT/LoRA
scripts/generate.py          Task 2/6 deterministic batched generation
scripts/build_pairs.py       blinded, randomized A/B pairwise files
scripts/judge_pairwise_kaggle.py  Task 7 resumable judge (kaggle_benchmarks)
scripts/plot_metrics.py      training curves
notebooks/00..06_*.ipynb     one Kaggle notebook per stage (generated by tools/make_notebooks.py)
eval_sets/                   fixed eval sets (HH 300 provided; persona 24; AlpacaEval 300 is built with seed 42)
tests/                       public smoke tests + extra edge-case and parser tests
```

## Implementation choices (documented for the report)

| Item | Choice |
|---|---|
| Prompt template | `### Instruction:\n{instruction}\n\n### Response:\n`, response followed by `<\|endoftext\|>` |
| Tokenization | prompt and response encoded separately without special tokens, concatenated; EOS appended **before** right-truncation to `max_length` |
| Labels | `-100` on prompt and padding (selected by position, so pad == EOS in Qwen is handled) |
| Padding | right padding to the longest row in the batch |
| SFT loss | mean NLL over all response tokens of the effective batch (adapter: of the given batch) |
| DPO loss | batch mean of `-log σ(β[(π_c − π_r) − (ref_c − ref_r)])`, response tokens only |
| Reference | frozen copy of the SFT best checkpoint on `cuda:1`, `requires_grad_(False)` + `no_grad` |
| Precision | fp32 trainable weights, fp16 autocast, `GradScaler`, log-softmax in fp32 |
| Data filters | single-turn only, non-empty, chosen ≠ rejected, UF score ties dropped, formatted prompt ≤ 256 tokens |
| DPO checkpoint | best validation reward accuracy (strict `r_w > r_l`), ties broken by margin; plus final |
| Decoding | greedy, `repetition_penalty=1.1`, `max_new_tokens=512`, same for every model in a comparison |

The default values in our scripts are the guide values (SFT: lr 2e-5, 3% warmup + cosine, wd 0.1, 2×16 and DPO: β 0.1, fixed lr 1e-6, AdamW, 1×32, with 1 epoch, clip 1.0, context 512 and seed 42 for both). Every run also saves the settings it actually used in `outputs/<run>/config.json`, so these can be checked against the report.

## Running on Kaggle (T4 x2)

| Notebook | Inputs | How it was run | Time (actual) |
|---|---|---|---|
| `00_dev_smoke` | – | interactive | ~15 min |
| `01_sft` | – | Save & Run All (Commit) | 1.51 h SFT (+ base generations on cuda:1) |
| `02_dpo_hh` | `01_sft` output | Commit | 0.90 h |
| `03_dpo_uf` | `01_sft` output | Commit | 1.47 h |
| `04_lora_persona` | – | Commit | ~2 min training |
| `05_generate` | outputs of 01–04 | Commit | ~45 min |
| `06_judge` | `05_generate` output | Kaggle **Benchmarks** notebook, no GPU, run interactively (benchmark notebooks cannot be committed; the judge is resumable) | ~40 min per judging pass |

Each notebook can be imported with **File → Import Notebook** or by uploading the `.ipynb`. The first cell of every notebook clones this repo and installs the dependencies without reinstalling Kaggle's PyTorch, so a notebook can be run on a fresh session as it is.

The tests can be run locally with `PYTHONPATH=. python -m pytest -q tests/` which runs the public adapter tests and our own edge-case and parser tests.

## Results (judge: `google/gemini-3.6-flash`, every pair judged in both A/B orders)

We judged every pair twice with A and B swapped, and a model only gets a win if it wins in both orders, otherwise we count it as a tie.

| Comparison | Eval set | DPO W / L / T | Win rate (excl. ties) | 95% CI | p (sign test) |
|---|---|---|---|---|---|
| HH-RLHF DPO vs SFT | HH synthetic, 300 | 108 / 68 / 124 | 61.4% | 54–68% | 0.003 |
| UltraFeedback DPO vs SFT | AlpacaEval subset, 300 (seed 42) | 78 / 98 / 124 | 44.3% | 37–52% | 0.15 |
| LoRA-DPO vs SmolLM2-360M-Instruct | persona prompts, 24 | 8 / 13 / 3 | 38.1% | 21–59% | 0.38 |

For the persona model we also looked at each criterion separately, where it gets style 9/0/15, helpfulness 5/13/6 and safety 2/1/21 against the base model (both orders). All the numbers are in `outputs/eval/final_stats.json`.
